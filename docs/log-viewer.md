# 运行日志

两个服务分别提供日志页面：

- 模拟服务：`/#server/logs`。
- 采集网关：`/#gateway/logs`。

页面支持关键词搜索、级别、模块和时间范围筛选；网关还支持机组筛选。关键词同时匹配日志正文、请求编号和结构化字段，可配合请求编号排查某次管理操作。时间在页面按浏览器本地时区显示，查询发送 RFC3339 时间。

默认每 2 秒刷新最新页。关闭“自动刷新”后保持当前结果，仍可手动刷新。查看较早分页时自动停止轮询；后续页携带首屏 anchor，以避免新日志插入造成重复或跳行。浏览历史页期间检测到服务重启，或较早记录已淘汰时，页面会提示并调整查询。切换服务时各自保留筛选条件。

日志详情展示完整的缓存正文和结构化字段；“导出当前页”只导出当前页结果与查询条件。连接失败时保留同一查询最近成功的数据；HTTP 404 提示更新并重启服务。

## 日志来源与范围

`GET /api/server/logs` 和 `GET /api/gateway/logs` 分别代理对应服务的 `/api/logs`。每个服务最多保留 3000 条当前进程日志，日志文本预算 8 MiB。重启后清空，旧文件日志和轮转档案不在本次查询范围。

捕获沿用服务端的记录级别与脱敏处理。DEBUG 筛选不会开启服务端的 DEBUG 记录：模拟服务可用 `--log-level debug`，网关使用 `logger.level='debug'`，修改后重启对应服务。模拟服务还会接入标准库日志，包含 OPC UA SDK 通过标准日志输出的消息。

缓冲按条数和文本预算限制；超长正文和字段会截断，过大的记录可能省略，页面显示淘汰计数。读取成功的日志接口请求不写入自身访问日志，以免轮询产生噪声。查询过程中不读磁盘，不接受文件路径，也不提供删改操作。

## 升级与验证

首次使用需重新构建并重启两个 Go 服务，再刷新前端。旧服务缺少 `/api/logs` 时会显示明确提示。

验证覆盖缓存容量和字节预算、并发读写、时间与组合筛选、稳定分页、字段脱敏和 UTF-8 截断；浏览器检查搜索、空结果、详情、暂停、错误恢复、服务重启处理及手机布局。两个后端使用同一查询契约，并独立包含 `internal/logstore`，便于分别构建与部署。
