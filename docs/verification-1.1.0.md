## 接口兼容性

旧版 `GET /api/nodes` 缺省继续直接读取设备；新 UI 自动轮询明确传 `source=cache`。旧版设备写入与配置路由保留。新 UI 登录会校验缓存及回读能力，以避免配套新 UI 却仍运行旧网关。

模拟服务仍只提供 API，不包含页面。新增 `/api/health`、`/api/version`、`/api/capabilities`、`/api/simulation/status`、`/api/simulation/validate` 及健康、指标路由。网关新增缓存、单点回读、重新发现、运行配置和配置历史等管理接口。

- 两个 Go 工程已通过 `go vet ./...` 与完整 `go test -race ./...`；后续新增模拟轨迹和缓存计费修正又分别通过相关竞态回归。

## 启用新版本

先停止旧的后端和前端进程，再从三个工程的父目录执行：

```sh
npm --prefix ./opc-console-ui run start:local
```

仅检查配置、二进制和端口：

```sh
npm --prefix ./opc-console-ui run check:local
```

已有独立启动方式继续可用。新 Go API 需要重启后端进程才会生效。联合脚本默认优先读取 `opc-gateway-go/config/config.toml`，不存在时使用现有示例配置；它不会改写配置文件或启动 Kafka。

首次安装或依赖变化时，在前端执行 `npm ci`。前端的 Git 仓库已在本地初始化，没有创建远端仓库、推送或部署，也不把本地 CI 文件的存在描述为远端执行成功。
